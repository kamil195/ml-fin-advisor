Portfolio Project · ML Fin-Advisor

Model Performance Metrics

A personal-finance ML system that classifies bank transactions into 30 spending categories, forecasts next-month category spend, and generates personalised budget recommendations using linear programming. Built with LightGBM, XGBoost, and Holt-Winters Exponential Smoothing.

All metrics below are measured on 100% synthetically generated transaction data — no real bank records or real user behaviour was used at any point. This is a personal portfolio project, pre-revenue, not yet validated against real-world data. Where a metric does not meet its design target, that is stated clearly and not hidden.

Architecture details ›
  • Stage 1 — LightGBM base learner: 800 trees, max depth 10, lr 0.05, 127 leaves, class-balanced weights
  • Text features: TF-IDF on character n-grams (2–4), max 5,000 vocab, compressed to 128 dimensions via Truncated SVD on merchant name + raw description
  • Numerical features: amount, MCC code, account type, channel, temporal signals (hour, day-of-week, month)
  • Stage 2 — XGBoost meta-learner: trained on 5-fold out-of-fold LightGBM probabilities concatenated with original features (300 trees, max depth 5, lr 0.08)
  • Training data: 24,516 rows, 30 synthetic users, 2024-03-01 to 2024-12-31; temporal split (last 4 months held out: 2 val + 2 test)

Passing tests cover: Transaction Pydantic model validation, currency/country normalisation, category hierarchy integrity, MCC code lookup, batch properties, mock data generation (row count, signed amounts, income presence), CSV ingestion (valid rows, invalid rows, missing file, quality checks, duplicate detection), and a full generate-then-ingest round-trip.

Intentionally skipped test: test_classifier_training_learns_better_than_random_baseline (tests/unit/test_classifier_training.py)

This test exercises the standalone ClassifierTrainer path in src/models/classifier/train.py (MLP + TextTower + meta-learner), which is not the model served in production. The served classifier artifacts live in models/serving/ and are produced by run_pipeline.py (LightGBM + XGBoost meta-learner). Because that parallel training path is currently disconnected from serving, the test is marked @pytest.mark.skip so CI does not report a false failure — it is not an active test or a current bug.
